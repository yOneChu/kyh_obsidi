## AI활용사례 제목


### 1.제목: 
- AI기반 설계BOM 검증 에이전트 구축  -> AI기반 설계BOM 검증 플랫폼 구축하고 싶다.

**Antigravity 기반 설계 BOM 자동 검증 AI 에이전트 구축**  
— 규칙(Rule) 문서 기반 전수 검증을 통한 JQPR 사전 예방


**사용자 정의 규칙 기반 설계 BOM 검증 AI 에이전트 구축**  
— 전수 검증 자동화를 통한 JQPR 사전 예방 및 업무 시간 단축


### 2.AI를 활용하게 된 배경 또는 기존 업무의 불편사항
-AI를 활용하기 전 기존 업무방식과 불편했던 점 또는 해결하고자 했던 문제를 작성해주세요.


금일 설계가 완료된 전 현장의 BOM을 사람이 일일이 전수 조사하는 방식에는 명확한 한계가 있었습니다. 검증 대상이 방대해 실질적으로 전수 검사가 어렵고, 수작업에 의존하는 특성상 누락과 오류를 원천적으로 배제할 수 없었습니다. 이렇게 걸러지지 못한 오류는 결국 JQPR로 이어져 설계자에게 재작업 부담과 스트레스로 되돌아왔습니다.

또한 다른 업무가 병행되는 현실에서는 BOM 검증에만 하루를 온전히 투입하기 어렵고, 검증이나 데이터 분석 자체를 수행할 시간을 확보하지 못하는 경우도 잦았습니다.
특정 조건의 자재 분포를 파악하거나 보고서를 작성하는 작업 역시 데이터를 수기로 추출·정리해야 해 **건당 2시간 이상**이 소요되곤 했습니다.

이에 각 자재별로 준수해야 할 검증 규칙을 문서로 정의해 두고, 요청 시 금일 설계된 모든 BOM을 규칙 기준으로 일괄 검증하는 AI 에이전트를 직접 고안하였습니다. 사람이 수행하면 하루가 소요되는 검증 작업을 10분 이내에, 2시간 이상 걸리던 분석·보고 작업을 5분 이내에 처리하고, 문제 구간을 자동으로 식별해 결과 보고서 형태로 제공하는 것을 목표로 하였습니다.


### 3.구체적인 활용 방법

본 에이전트의 핵심은 **검증 로직이 코드에 고정되어 있지 않고, 사용자가 정의한 규칙(Rule)에 따라 동작한다는 점**입니다. 

따라서 비표준 입력 여부, 특정 수배 부품의 수량 검증, PLAN-C 유형별 자재 분포 분석 등 담당자가 정의하기에 따라 검증 대상과 방식이 사실상 무한히 확장됩니다. 
하나의 도구로 정형화된 한 가지 검사만 수행하는 것이 아니라, 규칙만 추가하면 새로운 검증 시나리오를 즉시 적용할 수 있습니다.


본 프로세스에서 **사용자가 직접 수행하는 작업은 1~2단계뿐이며, 3단계부터 6단계까지는 에이전트가 전 과정을 자동으로 처리**합니다.

**［사용자 수행 영역］**
1. **규칙 정의** — 자재별·항목별로 준수해야 할 검증 규칙(Rule)을 상세히 문서화한다.
2. **자연어 요청** — Antigravity에 "금일(또는 어제) 설계 완료된 현장의 BOM을 검증해줘"와 같이 요청한다.

**［에이전트 자동 처리 영역］**
3. **데이터 연계** — 에이전트가 요청을 자연어로 해석한 뒤, 직접 구축한 중간 서버를 경유해 PLM/SAP에 접속하고, 검증에 필요한 쿼리를 생성해 데이터를 조회한다.
4. **데이터 추출** — 검증 대상 데이터를 자동으로 추출한다.
5. **규칙 검증** — 추출 데이터를 전처리한 후, 사전에 정의한 규칙에 위배되는 항목이 있는지 검증한다.
6. **결과 보고** — 검증 결과와 문제 구간, 분석 내용을 보고서 형태로 제공한다.

즉, 설계자는 검증 규칙을 정의하고 자연어로 요청하기만 하면, 이후 데이터 조회·추출·전처리·검증·보고에 이르는 전 과정이 사람의 개입 없이 자동으로 수행됩니다.


**［프롬프트 예시］**
- 오늘 설계완료된 현장의 BOM에서 비표준관려해서 'SPECIFY' 입력안된 부분있는지 찾아줘.
- 'A' 현장의 설계 BOM 검증해줘.
- 오늘 or 한달 간 설계완료된 현장 중, PLAN-C에 해당하는 자재가 몇 개인지 그리고 각 현장별 어떤 자재들이 수배되었는지 분석해서 보고해줘.

### 4.활용 결과 및 기대 효과
- 금일 설계 완료된 현장 BOM을 세부 규칙 단위까지 **10분 이내에 전수 검증** 가능 (수작업 시 하루 소요)
- 데이터 추출·분석·보고서 작성 작업을 **기존 2시간 이상에서 5분 이내로 단축**
- 반복적 수작업 검증에서 벗어나 **업무 스트레스 및 피로도 감소**
- 검증·분석에 투입되던 에너지를 절감하여 **생산성이 높은 핵심 업무에 집중**
- 오류의 조기 발견을 통한 **JQPR 발생 및 재작업 감소**
- 개인이 정의한 규칙에 따라 **다양한 관점의 검증·분석을 무한히 확장** 가능하여, 하나의 에이전트로 폭넓은 업무 니즈에 대응

### 5.장점
- **압도적 시간 절감**: 하루가 소요되던 BOM 전수 검증을 10분 이내로, 2시간 이상 걸리던 데이터 분석·보고 작업을 5분 이내로 단축하여, 설계자의 가용 시간을 실질적으로 확보한다.
- **검증 시나리오의 무한 확장성**: 검증 로직이 사용자 정의 규칙에 따라 동작하므로, 비표준 검증·수량 검증·자재 분포 분석 등 규칙을 추가하는 만큼 검증 범위가 무궁무진하게 확장된다. 하나의 도구로 다양한 업무 니즈를 흡수할 수 있다.
- **전수 검증 실현**: 샘플링이 아닌 대상 BOM 전체를 빠짐없이 검사하므로 검증 커버리지가 대폭 향상된다.
- **검증 기준의 표준화·지식 자산화**: 검증 규칙이 담당자 개인의 경험이 아닌 문서로 명문화되어, 담당자가 바뀌어도 동일한 품질의 검증이 유지되고 속인화(屬人化)를 방지한다.
- **낮은 사용 진입장벽**: 별도 프로그램 조작 없이 자연어 요청만으로 검증을 실행할 수 있어 설계자 누구나 활용 가능하다.
- **실시간 데이터 기반 검증**: 중간 서버를 통해 PLM/SAP 원본 데이터를 직접 조회하므로, 별도 수기 추출 없이 최신 데이터를 대상으로 검증한다.

### 6.한계점 및 주의사항
- **규칙 완성도 의존성**: 정의된 규칙 범위 내에서만 오류를 검출하므로, 규칙에 명시되지 않은 유형의 오류는 탐지되지 않는다. 규칙의 정합성과 완성도가 검증 품질을 좌우한다.
- **규칙 유지보수 공수**: 자재 사양·설계 기준 변경 시 규칙 문서를 지속적으로 갱신·관리해야 하며, 이를 소홀히 하면 검증 신뢰도가 저하된다.
- **오탐/미탐 가능성**: LLM 기반 판단 특성상 정상 항목을 오류로(false positive), 또는 실제 오류를 정상으로(false negative) 판정할 여지가 있어, **검증 결과는 참고 자료로 활용하고 최종 판단은 담당자 검토를 병행**하는 것이 바람직하다.
- **데이터 보안·권한 관리**: PLM/SAP 실데이터에 직접 접근하는 구조이므로, 접근 권한과 조회 범위를 명확히 통제하고 보안 정책을 준수해야 한다.
- **논리 정합성 검증의 편차**: 단순 입력 오류(공백·특수문자 등) 대비, 논리적 정합성 검증은 학습 품질에 따라 정확도 편차가 발생할 수 있어 결과 해석에 유의가 필요하다.
