# JAVA 방식 PID 추가 가이드  
  
JAVA 방식 PID 는 **PID 코드와 같은 이름의 메소드**를 Java 클래스에 추가하는 방식으로 동작한다.  
실행 시 `executeJAVA()` 가 리플렉션(`getClass().getMethod(pid, Map.class, List.class, Map.class)`)으로 메소드를 찾아 호출한다.  
  
---  
  
## 1. 어느 파일에 넣나  
  
시뮬레이터마다 실행 클래스가 다르다.  
  
| 파일 | 호출 위치 | 사용 화면 |  
|---|---|---|  
| `src/main/java/com/kyhslam/util/pidSimulatorUp/SimPIDJavaMethod.java` | `SimVariant.java` (METHOD = JAVA 분기) | **pidSimulatorUp** (`/simulateup/...`), Playground(`SimConsts` 사용) |  
| `src/main/java/com/kyhslam/util/simulate/PidJavaMethod.java` | `PidVariant.java` | 운영 버전 시뮬 (`PidVariant` 경로) |  
| `src/main/java/com/kyhslam/util/simulate/BlockPIDJavaMethod.java` | `BlockVariant.java` | Block 시뮬 |  
  
> **pidSimulatorUp 화면에서 쓰려면 `SimPIDJavaMethod` 에 반드시 넣어야 한다.**  
> 다른 시뮬에서도 필요하면 해당 클래스에도 같이 추가한다.  
> CALL 로 호출되는 하위 PID 도 같은 경로(`SimVariant` → `SimPIDJavaMethod`)로 실행된다.  
  
---  
  
## 2. 메소드 작성 형식  
  
`SimPIDJavaMethod` 기준:  
  
```java  
public SimVariantMap PID코드(Map elvEnt, List<Map> floorMasterList, Map partInfo) {  
    SimVariantMap result = new SimVariantMap();  
    String EL_XXX = SimUtil.NVL(elvEnt.get("EL_XXX"), "");   // 영업사양 읽기  
    // ... 로직 ...  
    result.put("O_결과키", 값);   // 결과 = OUTPUT 키  
    return result;}  
```  
  
### 규칙  
  
- **메소드 이름 = PID 코드** (대소문자까지 동일).  
  다르면 `NoSuchMethodException: JAVA에 해당 메소드 정의 안됨. PID : ...` 발생.  
- **`public`** 이어야 한다. (`getMethod` 는 public 메소드만 찾음)  
- **파라미터는 `(Map elvEnt, List<Map> floorMasterList, Map partInfo)` 3개, 순서 고정.**  
  `throws Exception` 은 붙여도 된다.  
- **반환 타입은 클래스별로 다르다.** 틀리면 컴파일은 되지만 실행 시 `ClassCastException` 이 난다.  
  
| 클래스 | 반환 타입 | 유틸 |  
|---|---|---|  
| `SimPIDJavaMethod` | `SimVariantMap` | `SimUtil` |  
| `PidJavaMethod` | `PidVariantMap` | `PidUtil` |  
| `BlockPIDJavaMethod` | `PidVariantMap` | `BlockUtil` |  
  
### 파라미터 의미  
  
| 파라미터 | 내용 |  
|---|---|  
| `elvEnt` | 호기 영업사양 (`EL_XXX` 키) |  
| `floorMasterList` | 층 정보 목록 (층별 Map, 예: `EL_EFPO`) |  
| `partInfo` | 부품 정보 (없으면 빈 Map) |  
  
---  
  
## 3. 다른 클래스에서 복사해 올 때 치환할 것  
  
`PidJavaMethod` → `SimPIDJavaMethod` 로 옮기는 경우:  
  
| 변경 전 | 변경 후 |  
|---|---|  
| `PidVariantMap` | `SimVariantMap` |  
| `PidUtil.` | `SimUtil.` |  
| `PidComDb`, `PidDb` (DB/COMDB 조회) | `SimComDb`, `ctx.getDb()` 등 (기존 메소드 방식 참고) |  
  
`PidJavaMethod` → `BlockPIDJavaMethod` 로 옮기는 경우는 `PidUtil.` → `BlockUtil.` 로 바꾼다.  
  
---  
  
## 4. DB 설정  
  
PID 헤더의 **METHOD 값이 `JAVA`** 여야 이 경로로 실행된다 (`SimConsts.METHOD_JAVA` 비교).  
METHOD 가 DB 이면 라인 로직으로 실행된다.  
  
JAVA 방식 PID 는 라인 정보가 없으므로, 화면에는 결과값만 표시된다 ("JAVA 실행결과").  
  
---  
  
## 5. 예시 : FUNCTION_FLOOR_COUNT  
  
층 목록에서 `EL_EFPO` 값별 개수를 센다.  
  
```java  
public SimVariantMap FUNCTION_FLOOR_COUNT(Map elvEnt, List<Map> floorMasterList, Map partInfo) {  
    partInfo = null; // partInfo는 input에 없음. 명시적으로 넣음.  
    SimVariantMap result = new SimVariantMap();  
    int O_MAIN = 0;    int O_UNDER = 0;    int O_ETC = 0;  
    if (floorMasterList != null) {        for (Map floorInfo : floorMasterList) {            String EL_EFPO = SimUtil.NVL(floorInfo.get("EL_EFPO"), "");  
            if ("MAIN".equals(EL_EFPO))                O_MAIN++;            else if ("UNDER".equals(EL_EFPO))                O_UNDER++;            else if ("ETC".equals(EL_EFPO))                O_ETC++;        }    }  
    result.put("O_MAIN", String.valueOf(O_MAIN));    result.put("O_UNDER", String.valueOf(O_UNDER));    result.put("O_ETC", String.valueOf(O_ETC));  
    return result;}  
```  
  
> `PidJavaMethod` 에서 그대로 복사해 반환 타입이 `PidVariantMap` 으로 남아 있으면 `SimPIDJavaMethod.executeJAVA` 의  
> `(SimVariantMap) m.invoke(...)` 에서 `ClassCastException` 이 난다.

## 6. 체크리스트  
  
- [ ] PID 헤더 METHOD = `JAVA`  
- [ ] 메소드 이름 = PID 코드 (대소문자 동일)  
- [ ] `public`, 파라미터 `(Map, List<Map>, Map)`  
- [ ] 반환 타입이 대상 클래스에 맞음 (`SimPIDJavaMethod` → `SimVariantMap`)  
- [ ] 유틸 클래스 치환 (`PidUtil` → `SimUtil` 등)  
- [ ] 필요한 시뮬 클래스 모두에 추가 (`SimPIDJavaMethod` / `PidJavaMethod` / `BlockPIDJavaMethod`)  
- [ ] 컴파일 후 pidSimulatorUp 화면에서 실행 확인
