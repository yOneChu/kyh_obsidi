# OneCycleFunc 기능 매뉴얼  
  
> 대상 클래스 : `src/main/java/com/kyhslam/service/OneCycleFunc.java`  
> 종류 : Spring `@Service` (다른 Bean 에서 `@Autowired` 로 주입받아 사용)  
  
PLM(DynaPLM) 화면에서 사람이 하나씩 누르던 작업을 HTTP 요청으로 대신 수행하는 클래스입니다.  
  
| 화면 작업                 | 함수                                  |     |
| --------------------- | ----------------------------------- | --- |
| 로그인                   | `login()`                           |     |
| WIP 생성                | `makeWip()`                         |     |
| 속성값 변경                | `changeAttr()` / `changeDesigner()` |     |
| 종속사양 산출               | `executeJongsoksung()`              |     |
| BOM 계산 (구성/자재/사양 전개)  | `bomCalStart()`                     |     |
| 동일정보 만들기 (TEST 호기 생성) | `makeEqualInfo()`                   |     |
  
위 작업을 순서대로 한 번에 묶어 실행하는 **사이클 함수**도 제공합니다.

## 1. 설정  
  
`application.properties` 에 아래 값을 설정합니다. 계정을 인자로 받지 않는 함수는 모두 이 계정을 사용합니다.  
  
| 키 | 설명 | 기본값 |  
|---|---|---|  
| `plm.base-url` | PLM 서버 주소 | `http://plmpro.hdel.co.kr` |  
| `plm.user-id` | PLM 로그인 사번 | `2035570` |  
| `plm.password` | PLM 비밀번호 | (빈 값) |  
| `plm.model` | 로그인 화면 model 콤보값 (DynaPLM v5 = `80001764`, PLM_China = `950695d0`) | `80001764` |  
  
> 호기번호 → ouid 조회는 PLM DB 를 직접 조회하므로 `PLMDBConnection` 의 DB 접속 설정도 필요합니다.

## 2. 기본 개념  
  
### 프로젝트호기번호 (productNo)  
`ELV_INFO$VF.MD$NUMBER` 값. 예) `TEST-632560`  
  
### 영업사양 ouid (vfOuid)  
PLM 이 객체를 식별하는 값. `elv_info$vf@` + 16진수 ouid 형태입니다. 예) `elv_info$vf@ac45dd18`  
단계별 함수는 모두 이 값을 받습니다. 호기번호로부터 얻으려면 `toObjectOuid(productNo)` 를 사용합니다.  
  
### 세션 (PlmSession)  
`login()` 이 돌려주는 객체로, PLM 의 `JSESSIONID` 쿠키를 들고 있습니다.  
단계별 함수는 모두 첫 번째 인자로 세션을 받으며, **같은 세션으로 여러 단계를 연달아 호출**하면 됩니다.  
  
- 호출마다 자기 세션을 따로 가지므로 여러 작업을 동시에 돌려도 서로 영향을 주지 않습니다.  
- selenium 등으로 로그인한 쿠키를 쓰고 싶다면 `new PlmSession()` 후 `setCookie("JSESSIONID", 값)` 으로 직접 넣을 수 있습니다.  
  
### 속성 맵 (attrs)  
바꿀 속성을 `{특성코드: 값}` 형태의 `Map` 으로 넘깁니다. 개수 제한 없이 한 번에 변경합니다.  
값이 `List` 등 `Collection` 이면 콤마(`,`)로 이어 붙여 전송합니다.  
  
```java  
Map<String, Object> attrs = new LinkedHashMap<>();  
attrs.put("EL_ZFDA", "20261003");                          // 기계구조 최초설계  
attrs.put("designer", List.of("2035570", "2014718"));       // -> "2035570,2014718"  
```  
  
자주 쓰는 특성코드  
  
| 특성코드 | 의미 |  
|---|---|  
| `designer` | 담당 설계자 사번 (여러 명이면 List 또는 콤마 구분) |  
| `MANAGER_M` | 기계 담당자명 |  
| `MANAGER_E` | 전기 담당자명 |  
| `md$user` | 담당자명 |  
| `md$description` | 현장명 |  
| `EL_ZFDA` | 기계구조 최초설계 |  
| `EL_ZFDB` | 기계의장 최초설계 |  
| `EL_ZFDC` | 전기구조 최초설계 |  
| `EL_ZFDD` | 전기_의장 최초설계 |

## 3. 사이클 함수 (한 번에 실행)  
  
호기번호만 넘기면 ouid 조회, 로그인, 각 단계를 순서대로 처리하고 결과 객체를 돌려줍니다.  
각 함수는 설정 계정을 쓰는 버전과 `userid`, `pwd` 를 직접 넘기는 버전이 있습니다.  
  
### 3.1 원사이클 — `runOneCycle`  
  
```java  
OneCycleResult runOneCycle(String productNo)  
OneCycleResult runOneCycle(String productNo, String userid, String pwd)  
OneCycleResult runOneCycle(String productNo, Map<String, ?> attrs)  
OneCycleResult runOneCycle(String productNo, Map<String, ?> attrs, String userid, String pwd)  
```  
  
**처리 순서**  
  
```  
호기번호 → ouid 조회 → 로그인 → WIP 생성 → [속성값 변경] → 종속사양 산출 → BOM 계산  
```  
  
- `attrs` 를 넘기지 않거나 비어 있으면 **속성값 변경 단계는 건너뜁니다.**  
- WIP 생성이 실패해도(이미 WIP 인 경우 등) 다음 단계를 계속 진행합니다.  
- 속성값 변경 실패 / 종속사양 산출 응답 없음이면 그 자리에서 중단합니다.  
- BOM 계산까지 응답을 받으면 `success = true`.  
  
### 3.2 동일정보 원사이클 — `runEqualInfoCycle`  
  
```java  
OneCycleResult runEqualInfoCycle(String sourceNo, Map<String, ?> attrs)  
OneCycleResult runEqualInfoCycle(String sourceNo, Map<String, ?> attrs, String userid, String pwd)  
```  
  
원본 호기를 복사해 TEST 호기를 만든 뒤, 새 호기에 대해 사이클을 수행합니다.  
  
**처리 순서**  
  
```  
원본 호기번호 → ouid 조회 → 로그인 → 원본 WIP 생성 → 동일정보 생성(신규 호기)  
            → [신규 호기 속성값 변경] → 신규 호기 종속사양 산출 → 신규 호기 BOM 계산  
```  
  
- 결과의 `productNo` / `objectOuid` 는 **새로 만들어진 호기**, `sourceProductNo` 는 **원본 호기**입니다.  
- 동일정보로 만든 호기는 이미 WIP 상태라 WIP 생성은 원본에 대해서만 수행합니다.  
  
### 3.3 동일정보 만들기 — `runEqualInfo`  
  
```java  
EqualInfoResult runEqualInfo(String productNo)  
EqualInfoResult runEqualInfo(String productNo, String userid, String pwd)  
```  
  
**처리 순서**  
  
```  
원본 호기번호 → ouid 조회 → 로그인 → 동일정보 생성 → 신규 호기번호 조회  
```  
  
TEST 호기만 만들고 끝납니다. 결과의 `newProductNo` 로 신규 호기번호를 확인합니다.  
  
### 3.4 속성정보 변경 — `runAttrChange`  
  
```java  
AttrChangeResult runAttrChange(String productNo, Map<String, ?> attrs, boolean verify)  
AttrChangeResult runAttrChange(String productNo, Map<String, ?> attrs, boolean verify, String userid, String pwd)  
```  
  
**처리 순서**  
  
```  
호기번호 → ouid 조회 → 로그인 → 속성값 변경 → (verify=true 면) 변경 후 값 재조회  
```  
  
- `verify = true` 면 변경 후 값을 다시 읽어 `current` 에 담고, 요청값과 모두 같으면 `verified = true`.  
- 종속사양 산출 / BOM 계산은 하지 않습니다.

## 4. 단계별 함수  
  
사이클 함수를 쓰지 않고 원하는 단계만 골라 호출할 때 사용합니다.  
**순서 : `login()` 으로 세션을 얻고 → `toObjectOuid()` 로 ouid 를 얻은 뒤 → 각 단계 호출.**  
  
### 4.1 로그인 — `login`  
  
```java  
PlmSession login()                              // 설정(application.properties) 계정  
PlmSession login(String userid, String pwd)     // 지정 계정  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `GET /jsp/login/JsLogin.jsp` (세션 쿠키 발급) → `POST /LogIn.do` (`cmd=check`) |  
| 반환 | 성공 시 `PlmSession`, 실패 시 `null` |  
| 성공 판단 | 302 리다이렉트이고 이동 위치가 로그인 화면(`JsLogin`)이 아닐 때 |  
  
### 4.2 WIP 생성 — `makeWip`  
  
```java  
String makeWip(PlmSession session, String vfOuid)  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `POST /SalesObject.do` (`cmd=makeWip`) |  
| 반환 | 결과 메시지. 오류 페이지면 `PLM 시스템 오류 (...)` 같은 요약 문자열 |  
| 비고 | 재시도하지 않음. 이미 WIP 이면 오류 메시지가 오지만 다음 단계는 진행 가능 |  
  
### 4.3 속성값 변경 — `changeAttr`  
  
```java  
String changeAttr(PlmSession session, String vfOuid, Map<String, ?> attrs)  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `POST /Object.do` (`cmd=objectUpdate`) + 속성 맵 |  
| 반환 | 결과 메시지. 메시지 없이 200 이면 `"속성정보 변경 완료"`. 끝내 실패하면 `null` |  
| 재시도 | 최대 3회 (3초 간격) |  
  
### 4.4 담당 설계자 변경 — `changeDesigner`  
  
```java  
String changeDesigner(PlmSession session, String vfOuid, Object designer)  
```  
  
`changeAttr(session, vfOuid, Map.of("designer", designer))` 의 단축 함수입니다.  
`designer` 는 `"2035570"` 또는 `List.of("2035570", "2014718")`.  
  
### 4.5 종속사양 산출 — `executeJongsoksung`  
  
```java  
String executeJongsoksung(PlmSession session, String vfOuid)  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `POST /Object.do` (`cmd=executeAction`, `actionOuid=9507f844`) |  
| 반환 | 응답 json 의 `message`. 끝내 실패하면 `null` |  
| 재시도 | 최대 3회 (3초 간격) |  
  
### 4.6 BOM 계산 — `bomCalStart`  
  
```java  
String bomCalStart(PlmSession session, String vfOuid)                                  // c, m, f 모두  
String bomCalStart(PlmSession session, String vfOuid, String bc, String bm, String bf) // 원하는 전개만  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `POST /SubaeManager.do` (`cmd=bomCalStart`) |  
| 전개 옵션 | `BOM_C`(`c`) 구성전개 / `BOM_M`(`m`) 자재전개 / `BOM_F`(`f`) 사양전개. 안 쓰는 항목은 `null` |  
| 반환 | 응답 json 의 `message`. 끝내 실패하면 `null` |  
| 재시도 | 최대 3회 (3초 간격) |  
| 비고 | `vfOuid` 는 `ac45dd18` 처럼 ouid 만 넘겨도 되고, 내부에서 소문자 `elv_info$vf@...` 형태로 맞춤 |  
  
```java  
// 자재전개만 수행  
oneCycleFunc.bomCalStart(session, vfOuid, null, OneCycleFunc.BOM_M, null);  
```  
  
### 4.7 동일정보 생성 — `makeEqualInfo`  
  
```java  
String makeEqualInfo(PlmSession session, String vfOuid)  
```  
  
원본의 전체 특성값을 조회(`getObjectInfo`)한 뒤, 새 공사정보로 등록(`registObject`)합니다.  
  
| 항목 | 내용 |  
|---|---|  
| 반환 | 신규 공사정보 ouid. 실패하면 `null` |  
| 제외 항목 | `name@` 이 들어간 표시용 항목, `md$number`(PLM 이 새로 채번), `ouid`, 값이 null 인 항목 |  
  
신규 호기번호는 `findProductNo(신규 ouid)` 로 조회합니다.  
  
### 4.8 공사정보 등록 — `registObject`  
  
```java  
String registObject(PlmSession session, Map<String, String> data)  
```  
  
| 항목 | 내용 |  
|---|---|  
| 요청 | `POST /SalesObject.do` (`cmd=registObject`, `classOuid=860cebeb`) |  
| 반환 | 응답의 `iOuid` (신규 ouid). 실패하면 `null` |  
| 비고 | **재시도하지 않음.** 실제 등록은 됐는데 응답만 깨진 경우 재시도하면 호기가 중복 생성되기 때문 |  
  
보통은 직접 호출하지 않고 `makeEqualInfo` 를 통해 사용합니다.

## 5. 조회 함수  
  
| 함수 | 설명 | 반환 |  
|---|---|---|  
| `static String toObjectOuid(String productNo)` | 호기번호로 **WIP 상태인** 영업사양 ouid 를 DB 조회 | `elv_info$vf@xxxxxxxx`. 없으면 빈 문자열 |  
| `static String findProductNo(String vfOuid)` | ouid 로 호기번호를 DB 조회 | 호기번호. 없으면 빈 문자열 |  
| `JsonNode getObjectInfo(PlmSession, String vfOuid)` | 공사정보 전체 특성값 조회 (`POST /SalesObject.do`, `cmd=objectInfoAjax`). 최대 3회 재시도 | 특성코드 → 값 json. 실패 시 `null` |  
| `Map<String,String> getAttrValues(PlmSession, String vfOuid, Collection<String> codeNames)` | 지정한 특성코드의 현재 값만 조회 (속성 변경 확인용) | 특성코드 → 값. 조회 실패 시 빈 Map |  
  
> `toObjectOuid`, `findProductNo` 는 `static` 이라 세션 없이 `OneCycleFunc.toObjectOuid(...)` 로 바로 호출할 수 있습니다.

## 6. 결과 객체  
  
모든 결과 객체는 `@ToString` 이 붙어 있어 그대로 출력하면 전체 내용을 볼 수 있습니다.  
공통으로 `success`(성공 여부), `loginSuccess`, `message`(최종 메시지), `elapsedMillis`(수행 시간 ms) 를 가집니다.  
  
### OneCycleResult — `runOneCycle`, `runEqualInfoCycle`  
  
| 필드 | 설명 |  
|---|---|  
| `success` | BOM 계산까지 응답을 받았는지 |  
| `productNo` | 대상 호기번호 (동일정보 사이클이면 **신규** 호기번호) |  
| `sourceProductNo` | 동일정보 사이클의 원본 호기번호 (일반 원사이클이면 null) |  
| `objectOuid` | 대상 영업사양 ouid |  
| `makeWipMessage` | WIP 생성 결과 |  
| `attrMessage` | 속성값 변경 결과 (변경할 속성이 없으면 null) |  
| `attrCurrent` | 속성값 변경 후 다시 읽은 값 |  
| `jongsoksungMessage` | 종속사양 산출 결과 |  
| `bomMessage` | BOM 계산 결과 |  
  
### EqualInfoResult — `runEqualInfo`  
  
| 필드 | 설명 |  
|---|---|  
| `productNo` / `objectOuid` | 원본 호기번호 / ouid |  
| `newObjectOuid` | 신규 공사정보 ouid |  
| `newProductNo` | 신규 호기번호 (TEST 번호). 조회 못 하면 빈 문자열 |  
  
### AttrChangeResult — `runAttrChange`  
  
| 필드 | 설명 |  
|---|---|  
| `productNo` / `objectOuid` | 대상 호기번호 / ouid |  
| `requested` | 요청한 속성 (전송용 문자열로 변환된 값) |  
| `current` | 변경 후 다시 읽은 값 (`verify=true` 일 때만) |  
| `verified` | 요청값과 변경 후 값이 모두 일치하는지 |

## 7. 사용 예시  
  
```java  
@Autowired  
private OneCycleFunc oneCycleFunc;  
```  
  
### 7.1 원사이클 (속성 변경 없음)  
  
```java  
OneCycleFunc.OneCycleResult r = oneCycleFunc.runOneCycle("TEST-630231");  
System.out.println(r.isSuccess() + " / " + r.getMessage());  
```  
  
### 7.2 원사이클 + 속성값 변경  
  
```java  
Map<String, Object> attrs = new LinkedHashMap<>();  
attrs.put("EL_ZFDA", "20261003");  
  
OneCycleFunc.OneCycleResult r = oneCycleFunc.runOneCycle("TEST-630231", attrs);  
```  
  
### 7.3 동일정보 생성 → 속성 변경 → 종속사양 → BOM

## 8. 재시도 및 오류 처리  
  
### 재시도 정책  
  
| 함수                                                                 | 재시도                           |     |
| ------------------------------------------------------------------ | ----------------------------- | --- |
| `changeAttr`, `executeJongsoksung`, `bomCalStart`, `getObjectInfo` | 최대 3회, 3초 간격                  |     |
| 동일정보 생성 후 신규 호기번호 조회                                               | 최대 3회, 3초 간격 (채번이 늦게 보일 수 있음) |     |
| `makeWip`, `registObject`, `login`                                 | 재시도 없음                        |     |
  
### 타임아웃  
  
| 항목 | 값 |  
|---|---|  
| 연결 타임아웃 | 10초 |  
| 응답 대기 타임아웃 | 120초 (BOM 계산이 오래 걸림) |  
  
### 자주 보는 메시지  
  
| 메시지 | 원인 / 조치 |  
|---|---|  
| `프로젝트호기번호에 해당하는 영업사양(WIP)을 찾지 못했습니다` | 호기번호 오타, 또는 WIP 상태 버전이 없음 |  
| `PLM 로그인 실패. 아이디/비밀번호를 확인하세요.` | `plm.user-id` / `plm.password` 확인 |  
| `세션이 만료되었습니다. (로그인 화면 응답)` | 세션이 끊김. 다시 `login()` 후 호출 |  
| `PLM 시스템 오류 (status ...) / ERROR ID ...` | PLM 서버 오류 페이지. ERROR ID 로 PLM 로그 확인 |  
| `응답 확인 필요 (status ...)` | json 도 오류 페이지도 아닌 응답. 상태코드 확인 |  
  
### 로그  
  
각 단계는 콘솔에 `[WIP 생성]`, `[속성정보 변경 1회차]`, `[종속사양 산출 1회차]`, `[BOM 계산 1회차]` 처럼 단계명과 결과를 출력하고, 실패 시 `###` 로 시작하는 줄을 출력합니다.

## 9. 함수 한눈에 보기  
  
| 구분 | 함수 | 하는 일 |  
|---|---|---|  
| 사이클 | `runOneCycle(productNo[, attrs][, userid, pwd])` | WIP → (속성변경) → 종속사양 → BOM |  
| 사이클 | `runEqualInfoCycle(sourceNo, attrs[, userid, pwd])` | 원본 WIP → 동일정보 → (속성변경) → 종속사양 → BOM |  
| 사이클 | `runEqualInfo(productNo[, userid, pwd])` | 동일정보 생성 + 신규 호기번호 조회 |  
| 사이클 | `runAttrChange(productNo, attrs, verify[, userid, pwd])` | 속성값 변경 (+ 확인) |  
| 단계 | `login([userid, pwd])` | **로그인** → 세션 |  
| 단계 | `makeWip(session, vfOuid)` | **WIP 생성** |  
| 단계 | `changeAttr(session, vfOuid, attrs)` | **속성값 변경** |  
| 단계 | `changeDesigner(session, vfOuid, designer)` | 담당 설계자 변경 |  
| 단계 | `executeJongsoksung(session, vfOuid)` | **종속사양 산출** |  
| 단계 | `bomCalStart(session, vfOuid[, bc, bm, bf])` | **BOM 계산** |  
| 단계 | `makeEqualInfo(session, vfOuid)` | **동일정보 생성** → 신규 ouid |  
| 단계 | `registObject(session, data)` | 공사정보 신규 등록 |  
| 조회 | `toObjectOuid(productNo)` | 호기번호 → WIP ouid (static) |  
| 조회 | `findProductNo(vfOuid)` | ouid → 호기번호 (static) |  
| 조회 | `getObjectInfo(session, vfOuid)` | 전체 특성값 조회 |  
| 조회 | `getAttrValues(session, vfOuid, codeNames)` | 지정 특성값 조회 |
