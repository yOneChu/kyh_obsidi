Subject: [안내] AI-DB 연계 사용 기준 변경 및 검증 항목 회신 요청 (~[일자])

안녕하십니까. 수배로직설계팀 [성명]입니다.

AI-DB 연계 환경을 업무에 적극적으로 활용해 주셔서 감사합니다. 사용이 늘어나면서 몇 가지 리스크가 확인되어, 사용 기준을 아래와 같이 정리하여 안내드립니다.

※ 먼저 명확히 해드리면, 해당 환경은 조회(SELECT) 전용 계정을 사용합니다. AI가 데이터를 수정하거나 삭제할 수는 없으니 그 부분은 안심하고 사용하셔도 됩니다. 다만 아래 두 가지는 관리가 필요합니다.


【요약 3줄】

1) 로직 작성 등 단건·소량 조회는 기존과 동일하게 사용하시면 됩니다.
2) 로직 검증·BOM 검증은 검증 항목을 첨부 양식에 작성해 회신 부탁드립니다. 양식에 등록되지 않은 항목은 조회가 제한됩니다.
3) 향후 SQL은 제가 배포한 DB 정의서 기반으로만 실행됩니다.


────────────────────

■ 1. 기준이 필요한 이유 — 리스크는 두 가지입니다

(1) 운영계 DB 부하
연계 대상은 분석계가 아닌 운영계(Production) DB입니다. 조회 전용이라도 SELECT 문 자체가 부하를 발생시킵니다. AI가 생성하는 SQL은 문법적으로는 유효하지만 인덱스 구성과 데이터 볼륨을 고려하지 않기 때문에, 조건 없는 전체 조회나 대량 조인은 Full Table Scan과 장시간 세션 점유로 이어집니다. 이는 곰 PLM·로직 업무 화면의 응답 지연으로 나타납니다. 원하는 결과가 나올 때까지 프롬프트를 반복하는 사용 패턴은 그 부하를 그대로 배수로 늘립니다.

(2) 조회 결과의 정합성
AI가 생성한 SQL은 정의서의 컬럼 의미를 '해석'한 결과이지, 결과의 정합성을 보증하지는 않습니다. 활성 플래그, 최신 리비전 조건, 블록넘버 등 조건이 하나만 누락되어도 건수는 정상으로 보이지만 실제 집합은 전혀 달라집니다.
조회 자체는 DB에 영향을 주지 않지만, 그 결과가 타 부서의 데이터 정리 요청이나 의사결정의 근거로 사용될 때는 이야기가 달라집니다. 실제 수정은 수신 부서에서 이루어지므로, 추출 기준이 틀려 있으면 원복이 어려운 결과로 이어질 수 있습니다.


■ 2. 이렇게 사용해 주십시오 (업무별 구분)

○ 로직 작성 등 단건·소량 조회
   → 기존과 동일하게 자유롭게 사용. 부하 리스크 낮음.

○ 로직 검증 / BOM 검증 등 대량·반복 조회
   → 검증 항목을 사전 등록 (아래 3항) → 전용 API로 전환 후 사용.

○ 조회 결과를 타 부서에 전달하거나 데이터 정리·의사결정의 근거로 사용할 때
   → AI 결과를 그대로 사용하지 마시고, 사전 공유해 주시면 쿼리와 결과셋을 검증해 드리겠습니다.


■ 3. [회신 요청] 검증 항목 작성 — 첨부 엑셀 양식

현재 수행 중이거나 예정인 로직 검증·BOM 검증에 대해, 구체적으로 어떤 항목을 검증하시는지 첨부 양식에 작성하여 [일자]까지 회신해 주시기 바랍니다.
취합된 내용은 검토 후 자연어 조회 방식이 아닌 전용 API 형태로 순차 전환하여 제공드리겠습니다. 동일 검증을 반복하셔도 부하 없이, 그리고 일관된 기준으로 결과를 확인하실 수 있습니다.

※ [일자] 이후로는 양식에 등록되지 않은 검증 항목은 조회되지 않도록 제한할 예정입니다. 누락될 경우 해당 검증 업무가 중단될 수 있으니, 현재 사용 중인 항목은 빠짐없이 기재해 주시기 바랍니다. 기한 이후 추가로 필요한 항목은 5항의 요청 창구를 통해 상시 등록하실 수 있습니다.

[요청 배경]
첫째, DB 부하가 정보기술팀, PI팀에 인지될 경우 원인 소명 절차는 물론, 현재 사용 중인 연계 환경 자체에 제약이 걸릴 수 있습니다. 그 경우 지금 하고 있는 업무 중 일부는 오히려 이전보다 제한된 방식으로 되돌아가거나 아예 사용을 못할 수도 있습니다.

둘째, 대량 데이터 조회·검증은 실행계획과 인덱스 사용 여부, 세션 점유 시간까지 함께 고려해야 하는 영역으로, 서버·DB 운영 경험이 뒷받침되어야 판단이 가능합니다. 무엇을 검증해야 하는가는 담당자분들이 가장 잘 알고 계시므로, 항목은 공유해 주시고 조회 방식 설계는 제가 맡는 것이 효율적이라고 판단됩니다.


■ 4. 조회 허용 범위 일원화

앞으로 조회는 아래 두 가지 기준 안에서만 동작합니다.

  ① 제가 작성·배포한 DB 정의서 — 그 외의 정의서로는 SQL이 실행되지 않습니다.
  ② 양식에 등록된 검증 항목 — 미등록 항목은 조회가 제한됩니다.

- 정의서의 임의 수정·재배포 및 개인 보관본 사용은 중단해 주시기 바랍니다.
- 스키마는 지속적으로 변경되며, 구버전 정의서 기반의 조회는 오류 데이터의 직접적인 원인이 됩니다.
- 정의서와 연계 API는 제가 형상관리와 배포를 전담합니다.
